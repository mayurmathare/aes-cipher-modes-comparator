Security Vulnerability Lab

ECB Pattern Leakage Demonstration

Empirical proof that identical plaintext blocks yield identical ciphertext blocks in ECB

In Electronic Codebook (ECB) mode, each 16-byte block is encrypted with the key independently. Therefore, whenever two plaintext blocks have identical content, their resulting ciphertext blocks are 100% identical. In contrast, chaining modes like CBC XOR previous blocks and use an unpredictable IV, obliterating all repeated patterns.

Practical / TAE Theoretical Summary

Block Ciphers vs Modes

AES encrypts a single fixed block of 128 bits (16 bytes). Modes of operation describe how to repeatedly apply AES's single-block transformation to encrypt messages of arbitrary length securely.

Why IVs Matter

An Initialization Vector (IV) ensures that encrypting the exact same message twice under the same key produces completely distinct ciphertexts, thwarting replay and codebook matching attacks.

Stream Modes (CFB, OFB, CTR)

CFB, OFB, and CTR turn the block cipher into a stream cipher by generating a keystream that is XORed with the plaintext. Hence, ciphertext length matches plaintext length with zero padding overhead.

CTR Mode Advantage

CTR mode enables random access and simultaneous parallel processing of all blocks across multiple CPU cores, making it the mode of choice for modern TLS, IPSec, and disk encryption.
